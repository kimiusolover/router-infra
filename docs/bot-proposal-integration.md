# Two-stage bot proposal integration

Use two consumer-owned workflows, both pinned to one `router-infra` commit.
The preparation workflow is triggered by a push to `main` and may run the
repository's generation/test command. It has no write permission.

```yaml
name: prepare bot proposal
on:
  push:
    branches: [main]
permissions:
  contents: read
jobs:
  prepare:
    uses: OWNER/router-infra/.github/workflows/bot-proposal-prepare.yml@COMMIT_SHA
    with:
      test-command: make test
      allowed-change-paths: |
        docs/**
      protected-paths: |
        policy/**
      proposal-title: "docs: generated update"
      proposal-body: "Generated by the read-only bot preparation workflow."
```

The PR workflow must live on the consumer repository's default branch. It is
the only workflow that gets write permissions. It receives a successful run
only; it does not execute data from the artifact.

```yaml
name: create bot proposal PR
on:
  workflow_run:
    workflows: [prepare bot proposal]
    types: [completed]
permissions:
  contents: write
  pull-requests: write
jobs:
  create-pr:
    uses: OWNER/router-infra/.github/workflows/bot-proposal-pr.yml@COMMIT_SHA
    with:
      preparation-workflow-name: prepare bot proposal
```

Replace `OWNER` and `COMMIT_SHA` with the repository owner and a 40-character
lowercase `router-infra` commit. Repository rules must permit this token to
push only `bot/*`; they must not allow the workflow to merge, tag, release, or
push `main`.
